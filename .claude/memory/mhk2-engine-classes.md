The class is GameParameters+0x10: 0..2 stock, 3 = 200 cc, 4 = 250 cc, 5 = tuning. `gpuse.py 10` lists the 31 places that read it.

**What depends on the number of classes, and what the patch does there**
- Record tables, [3 classes][64 tracks], index `(class << 6) + track`: time trial highscores at gp+0x234 (0xB4 each), phantom headers at gp+0xAA04 (0x6C each, track 1-based). Ten `shl reg,6` sites call thunks that fold the new rows onto unused upper halves of stock rows: class 3 -> slots 160..191 (150 cc row), class 4 -> 96..127 (100 cc row), class 5 -> 32..63 (50 cc row). All are `0x160 - (class << 6)`. Sites: 0x4099A4, 0x412A9E, 0x412B0B, 0x41C788, 0x41C816, 0x41C976, 0x420817, 0x423B2F, 0x423BCE, 0x423D2C.
- Championship tables, [3][20] at gp+0x8934, 0x8C each: 5 times (float) at +0, 5 points (int) at +0x14, 5 names (16 bytes) at +0x28, 5 characters at +0x78. Index `class * 20 + id`. Ids: 2 = Meisterschaft 1, 3 = Meisterschaft 2; ids 0 and 1 never get a highscore (fn 0x412CF0 returns false); gp+0xFCB8 is an id table (0, 1, 2, 3). Folded in three steps: class 3 -> 50.., class 4 -> 30.., class 5 -> 10... Sites 0x412D0F, 0x412D9B, 0x420DDA.
- Class factor (0x437724, diff ratio / f and torque curve * f): table of five floats behind the new code; class 5 takes its "Übersetzung" from the tuning values.
- Pull (new in 1.4): the force function 0x43F700 multiplies the drive torque (0x43F7F4) and the traction limit (0x43FAFF) by the vehicle's accel factor `[v+0x268]`, which only power-ups change. Both `fmul` sites call `pull_mul`, which multiplies by the class's pull as well: table 1, 1, 1, 1.5, 2; class 5 its "Motorkraft". Power-ups therefore stack on the class.
- Per-level AI tables and the engine samples exist for three classes: class clamped to 2 at 0x43A504, 0x43A5BB (AI) and 0x42FC14 (sample). Since 1.9 the throttle of classes 3..5 is raised on top (`ai_throttle` at 0x43A5CA), see [[mhk2-computer-kart-ai]].
- Phantom header scan at every menu init (fn 0x412F20): loops classes 1..3 x 64 tracks over `phantom-%d-%02d.mhk2`. Three extra passes of 32 tracks for class numbers 4, 5, 6 into slots 160.., 96.., 32.. (after class 3 the write pointer goes back 32 entries, after 4 and after 5 it goes back 96).
- Engine class menu = menu page 8, built in fn 0x41A5A0 between 0x41B0C6 and 0x41B4E0. Item 0 heading, items 1..N the classes (button when gp+0xFD08 >= class, else a grey label built from "<color 128 128 128 255>"; since 1.9 "Tuning" is a button when gp+0xFD08 >= 5, else a label with the empty text 348, so the item numbers never change), then "Zurück", the hint, two separators. Row positions are plain `push imm32`: heading 0x41B0ED, 50 cc 0x41B13C, 100 cc 0x41B19C / 0x41B255, 150 cc 0x41B2DC / 0x41B395, "Zurück" 0x41B40E, hint 0x41B45A, separators 0x41B48D and 0x41B49A. The patch adds its entries from a jump at 0x41B3F4. Select handler: 0x41E1EF `cmp eax,N` (items 1..N set class = item - 1) and 0x41E1F4 `cmp eax,N+1` (back); the call that opens the next page (0x41E233) goes through `class_selected`, which sends class 5 to the tuning page.
- Class names are text 332 + class: highscore browser 0x41C0C0 and 0x41CBEF (class at menu+0x1AC), championship result pages 0x424076 (page 0x10) and 0x424857 (pages 0x11/0x12). Stock 335 is the class menu's "Zurück" and 336 its hint, so the patch takes "Zurück" from 323 and moves the hint to 342 (`push 150h` at 0x41B448); 337 is "Tuning".
- Highscore browser class cycling: `mov ecx,N` before `idiv` at 0x41ED48, 0x41EEB9, 0x41EF70, 0x41F0A4, 0x41F0DE, 0x41F1DC, 0x41F293 and `add eax,N-1` at 0x41ED8E, 0x41EEB5, 0x41F0DA, 0x41F1D8.
- Unlock chain: page setter 0x413DD0, page 0x1B (championship trophy page, code from 0x41430B). The player's rank is the position of kart 0 in gp+0x1FC[7]; only rank 0 in the full edition ([0x5C38D8] == 2) unlocks. Championship id 2: if bit `1 << class` of gp+0xFD0C is clear, set it and show text 580 + class (opens Meisterschaft 2 and tracks 5-8 of that class). Id 3: if class == gp+0xFD08 and class < 5 (`cmp edi,N` at 0x414571: stock 2, 1.4..1.8 4, 1.9 5), increment gp+0xFD08 and show text 584 + class. settings.dat is saved at once. For class 4 the first number would be 584, a stock text, so a thunk at 0x414540 turns it into 588; 587 (584 + 3) was free. Winning championship 2 in 250 cc (class 4) would show 588 as well, so a second thunk at 0x41457A (`add edi,248h`) turns that into 589 "Du hast die Tuning-Klasse freigeschaltet!". The tuning class's championship-2 bit in gp+0xFD0C (0x20) is set when its values are first created, so championship 1 there never shows a message; winning its championship 2 does nothing (class 5 < 5 is false).
- Track lock: fn 0x4130B0(track, class); in the full edition tracks 4..7 need the class's bit in gp+0xFD0C. Works for any class. The championship page checks each championship's tracks with it too (calls 0x41B597, 0x41B5CC, 0x41B95D), so it also locks Meisterschaft 2.
- Switch "Alles freigeschaltet" (1.10, user 2026-11-24: a visible options row above the 60 FPS switch, in place of the `--unlock` scripts; they stay for tests and closed games): dword `FREI` at gp+0x2D9C (UNLOCK_MARK, behind STDG; file 0x2D98). It bypasses the reads, it does not write the progress: `unlock_level` (eax = gp -> ecx = level, 5 while on) at 0x41B173 (100 cc row) and through `unlock_cmp2` at 0x41B2B9 (150 cc row), the patch's own 200 cc / 250 cc / Tuning rows and `champ_build` (Gegner button); `unlock_test` replaces `test [eax+0FD0Ch],edx` at 0x413110 in the track lock. The unlock chain (0x414501..0x414596) reads the real values, so a win while the switch is on counts. Options items: 7 / 8 the switch (heading, value), 9 / 10 the physics switch, 11 "Zurück"; text 288 (the only id below 400 free in text.csv and the patch). Test: `classtest.py unlockall`.

Nothing had to change for: phantom file names (class + 1), phantom import (0x40C360), race and ghost code, result list, name entry.

**Tuning class (class 5)**: what its seven values do, the downforce rules and the tests are in [[mhk2-tuning-class]]. How it is wired in:
- Seven ints in GameParameters at +0x2E4C (highscore entry of 50 cc, track 63: the names of rank 4 and 5), the number of the preset copied last at +0x2E68, marker "TUNE" at +0x2E7C (that entry's fifth character). The entry: 5 times, 15 lap times, 5 names of 16 bytes at +0x50, 5 characters at +0xA0. `tune_defaults` writes the defaults and sets the class's unlock bit when the marker is missing; it runs when the page is built and when a class 5 kart loads.
- Kart side, in the loader 0x437080: `class_factor` gives st0 = Übersetzung / 100 for class 5; the call to 0x42BFF0 at 0x437772 (drops the physics objects before they are rebuilt) goes through `tune_apply`, which scales car fields from a table. Motorkraft is applied in `pull_mul`. The loader reads every value fresh from karts.txt each time, so nothing compounds. A third hook, `downforce_cap` at 0x43FCE0 in the force function, limits the downforce in class 5 only.
- Since 1.7 the class has three pages: 0x1D (Vorlage and buttons), 0x1F "Kart", 0x20 "Welt"; the same builder and updater hooks serve all of them and page 0x1E (own presets). The gravity of class 5 is set by a hook on the call of RwPhysics::Init at 0x409048 (`world_gravity`); details in [[mhk2-tuning-class]]. The text below describes the 1.6 layout of page 0x1D; the item numbers changed in 1.7.
- The page is menu page 0x1D (the game's builders and updaters dispatch on pages up to 0x1C and ignore higher numbers). Builder: the last of the three builder calls in SetPage (0x413E20 `call 00422420`) goes through `page_build`. Input: the call to the main page updater (0x4149EA `call 0041D400`) goes through `page_update`, which calls the menu's own navigation (0x4117D0), reads "menu back / select / left / right" (0x4016A0 + 0x45C890 with the action's name) and returns 0xFFFFFF9D like the stock updater. Item 0 is the preset row "Vorlage", items 1..7 the value rows (all eight type 3: arrows), 8 "Zurücksetzen", 9 "Eigene Vorlagen" (page 0x1E, the own presets), 10 "Weiter" (preselected), 11 "Zurück", 12 the title. Row texts are wsprintf formats in text-20.csv (241..247 = 240 + item; 249 "Vorlage: %s" with a name from 250..263 or 264 "Ungespeichert"); the title is 240, "Zurücksetzen" 248. Left / right go through `tune_change`: item 0 copies a preset, items 1..7 `tune_step`; `tune_settext` rewrites one item's text in place (the Vorlage row after every step). Page 0x1E (own presets) is built and updated by the same two hooks; renaming a slot also hooks the result pages' updater (0x4149CC `call 00421970`). Details in [[mhk2-tuning-class]].
- Text ids: the game lists every text with an id from 400 to 499 as a track ("Available tracks" in log.txt); an override there adds tracks and the game stops before the menu. Free and used by the patch: 221..223, 240..269, 271..279, 343..348 (1.9), 589 (1.9). Still free: 206..209, 288, 289, 293..299, 305..309, 317..319, 324..329, 349, 355..357, 365, 366, 384..389, 395..399.
- A mouse click on a row's arrow arrives as "select" with menu+0x14C = 1 (left) or 2 (right), as in the stock options page; "select" on the row itself does nothing.
- All routines of the tuning code take addresses relative to one label (`call tune_base` leaves it in ebp), because they call each other.

A seventh class would land on slot 0x160 - 0x180 < 0: no free half row is left; it would need another storage scheme.

**Testing without keyboard** (sandbox, scripts in `.claude/sandbox/tools`)
- `prep_class5.py` = `prep_ghost.py` plus the one-shot "menu select" stub at two more reads: 0x41E1C9 (engine class menu) and 0x414FE2 (trophy page), prep_opt's one-shot left / right floats at the highscore browsers' reads (left 0x41EE67 and 0x41F18A, right 0x41EF20 and 0x41F243; they act on the class when item 1 is selected), and a stub for the tuning page's single input read (found by its byte pattern in the patch's section) that serves back / select / left / right from MENU_INJ. `--mouse` adds the simulated mouse.
- `classtest.py tuning tunemouse tunekart tttune menu tt250 tt200 champ oldsave browser` and `ghosttest.py main cc200 options`: on the final 1.4 build of 2026-11-19 235 and 66 checks, all passed, in one run each. Patch 1.5 with the Vorlage row (same day): 268 and 66, all passed, in one run each (`runs\preset1`). Patch 1.6 with the own presets (`tuneown ownmouse` added, same day): 317 and 66, all passed, in one run each (`runs\own1`).
- The trophy page can be opened straight from the main menu: set gp+0x1C = 1, class, gp+0x24 = championship id, gp+0xFD08 / gp+0xFD0C, write the finishing order to gp+0x1FC (seven ints, kart 0 first), then page 0x1B. For a championship highscore also gp+0x1E0 (points, int) and gp+0x1C4 (time, float). "Weiter" (item 0) leads to the name entry (page 0x13) when it is a top-five result.
- After confirming a championship name the page number stays 0x13 and menu+0x160 becomes 1; pressing again inserts the result again. Press once.
- The track menu (page 7) shows one track at a time (gp+0x20); a locked track has a grey row.
- Writing menu+0x14C (the arrow under the mouse) from outside does not survive the frame: the menu's navigation sets it from the mouse every frame. Use the simulated mouse to test arrow clicks.
- Patch 1.9 (2026-11-22): `classtest.py` all scenarios 420 checks and `ghosttest.py main cc200 options` 66 checks, all passed (`runs\v19`); the menu scenario checks levels 2..5 (the tuning row an empty label below 5), champ the 250 cc championship 2 message 589 and level 5, oldsave `--unlock` (level 4, mask bits 0..4) and `--unlock-tuning` (level 5).
- Computer karts: `ai_race.py <60 FPS build> out.csv --seconds 75 --cls N --track 0`, then `ai_progress.py`. 250 cc on the final 1.4 build: mean speed 43.2 (41.1 .. 45.1), top 55.1, nearly still for 10.9 s in total. The tuning class has its own script, `tune_races.py`.
- A forced select on a grey label row does select that class (the handler only checks the item number); with real input a label cannot be selected, same as for locked 100 cc / 150 cc in the stock game.
